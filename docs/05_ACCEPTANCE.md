# 05. Postun Beta — приёмка и порядок реализации

**Редакция 2.0-beta · 04.11.2026.** Публичная бета — целевой режим запуска. Эта матрица описывает необходимые испытания, а не уже выполненные тесты приложения.

## 1. Выпуск небольшими проверяемыми шагами

| Шаг | Результат | Условие перехода |
|---|---|---|
| B0. Baseline | Существующий репозиторий, выбранные Cloudflare account и ресурсы, версии инструментов | Проверены права и отсутствие конфликтующих изменений |
| B1. Telegram spike | Авторизация и read-only MTProto в реальном Workers runtime | QR/2FA, сохранение сессии, cold start и чтение проходят |
| B2. Защищённое ядро | OAuth, account isolation, квоты, отключение, IDP | Отрицательные тесты не раскрывают данные другого аккаунта |
| B3. Публичный сайт | postun.org с приглашением бета-тестеров и реальным статусом функций | HTTPS, корректные ссылки и уведомления; секретов в сборке нет |
| B4. Клиенты и медиа | Проверенные подключения ChatGPT и Claude Code, файлы | Отдельное доказательство каждого заявленного сценария |
| B5. Self-host | Чистая установка в другом Cloudflare account | Нет зависимости от credentials или backend нашего сервиса |

B3 можно выпускать до завершения B4, но незавершённую функцию нельзя показывать работающей. Кнопка подключения реальной переписки появляется после B2 и успешного теста соответствующего клиента. Публичность сайта и открытый исходный код не отменяют технические барьеры доступа.

## 2. Матрица обязательных тестов

| ID | Проверка | Ожидаемое поведение |
|---|---|---|
| ID-01 | Подмена Telegram OIDC issuer/audience/nonce или неподписанный токен | Вход отклоняется, аккаунт не создаётся |
| ID-02 | OIDC sub отличается от Telegram ID | Идентификаторы не смешиваются; подписка и привязка используют проверенную связь |
| ID-03 | Повтор callback, истёкший login state, подмена QR login intent | Отказ без привязки чужой сессии |
| ID-04 | 2FA и DC migration во время входа | Корректное завершение либо понятная ошибка; секреты не логируются |
| MT-01 | Eviction DO, cold start, повторный deploy | Сессия восстанавливается без повторной привязки и без plaintext на диске |
| MT-02 | Одновременные запросы двух клиентов к одному аккаунту | Ограниченная сериализация, отсутствие конкурирующих session owners |
| AU-01 | Отсутствует токен; неправильный resource/issuer/scope | 401/403 до обращения к Telegram |
| AU-02 | Подменены account_id, principal_id, pagination cursor | Доступ только к разрешённым аккаунтам grant |
| AU-03 | Новый аккаунт добавлен после выдачи grant | Старый grant автоматически доступа не получает |
| AU-04 | Grant отозван, но KV отвечает старым значением | Authoritative DO запрещает новые операции |
| AU-05 | Отключение во время файла | Поток останавливается на ближайшей проверке; будущие Range отклоняются |
| AD-01 | IDP login без project role либо с чужим org/project | 403, даже если пользователь успешно аутентифицирован |
| AD-02 | Удаление роли, logout, локальная блокировка subject | Доступ прекращается в проверенный срок; старый JWT не считается свежей ролью |
| AD-03 | Компрометация кода Admin Worker в тесте | По bindings нет доступа к session vault, Control D1 и OAuth KV |
| AD-04 | CSRF и отсутствие MFA/нужной policy | Изменение запрещено; политика MFA подтверждена реальным входом |
| Q-01 | 101 конкурентная успешная операция при лимите 100 | Квота не превышена; reservation/commit атомарны в одном DO |
| Q-02 | Retry после сбоя/таймаута, совпадающий idempotency key | Нет двойного начисления одной операции; UNKNOWN не объявляется success |
| Q-03 | Частичная передача файла и повторный диапазон | Счётчик байтов отражает фактически выданный объём, включая повтор |
| PR-01 | Синтетические маркеры в сообщении, токене, имени файла | Маркеры отсутствуют в logs, traces, D1, KV и постоянных DO-таблицах содержимого |
| PR-02 | SDK exception, raw Telegram error, browser error report | Наружу только безопасный код ошибки, без credential и приватного текста |
| F-01 | Небольшой файл, 20 МБ, 100 МБ, затем целевые 512 МБ | Поток, ограниченная память, контроль размера, корректное окончание |
| F-02 | Размер выше configured max, неверный Range, отмена клиента | Ранний отказ/abort; ненужная передача из Telegram прекращается |
| F-03 | Чужой/истёкший download intent, повтор после отзыва | Отказ; ссылка не превращается в публичный bearer-доступ |
| F-04 | Файл в клиенте ИИ | Скачивание и появление пригодного для анализа вложения проверяются отдельно |
| CI-01 | Fork PR и preview с недоверенным кодом | Никаких production secrets, bindings и deploy permissions |
| CI-02 | Миграция на непустых синтетических данных | IDs, связи, квоты, ciphertext и deny state сохраняются |
| CI-03 | Откат к предыдущему совместимому артефакту | Работает на расширенной схеме; база не откатывается автоматически |
| SH-01 | Установка из публичного репозитория | Собственные ресурсы, ключи, Telegram app и IDP; нет обязательного обращения к postun.org |

Не следует сохранять полные tool results ради идемпотентности. Если ответ был утерян, сервис может повторно прочитать разрешённый источник и не начислить операцию повторно; содержимое при этом могло измениться. Это не гарантия повторения тех же байтов.

## 3. Матрица клиентской совместимости

Для каждого клиента записываются версия/режим, дата, deployment SHA и отдельные результаты: OAuth discovery, выдача/refresh токена, read tools, отзыв, media metadata, оригинальные байты, вложение для анализа. Статусы: PASS, FAIL, NOT_RUN, UNSUPPORTED — без объединения в одну отметку «поддерживается».

Минимум: обычный ChatGPT с custom MCP и Claude Code с remote HTTP MCP. Другие клиенты и задания по расписанию проверяются отдельно. Доступность MCP в чате не доказывает его доступность во всех режимах агентов. [S18–S19]

Реальные аккаунты для приёмки — специально подготовленные тестовые. Утверждение «512 МБ поддерживается» допустимо только после успешного теста соответствующего пути. Непроверенный максимальный размер отображается как цель, а не активная гарантия.

## 4. Эффективность и стоимость

Измерить CPU каждого Worker и DO, duration DO, пиковую память isolate, число внешних fetch/socket operations, размер бандла, фактические bytes, долю ошибок и задержку ответа. Не выводить стоимость из одного числа пользователей.

Проверить отсутствие постоянных исходящих соединений при простое. Провести нагрузку сначала на синтетическом transport adapter; реальные запросы Telegram — ограниченно, без обхода FloodWait. Free 10 мс CPU для HTTP Worker и лимиты DO — разные ограничения. Файл не буферизуется целиком ни в Worker, ни в DO, ни в библиотеке. [S05–S08]

Нельзя улучшать метрику ценой отключения TLS, account isolation, проверки grant или редактирования логов. Если Free недостаточен, предоставить измерение и расчёт перед платным включением. Самостоятельно переключать тариф запрещено.

## 5. Доказательства выпуска

Отчёт содержит commit SHA, точные dependency versions, environment, deployment ID, время, список тестов и безопасные результаты. Не включать Telegram session strings, содержимое документов, auth cookies, токены или идентификаторы чужих чатов.

Готовность публичной беты означает пройденные применимые B1/B2/B3/B4 и видимый статус Beta. Отдельные media/agent-функции могут оставаться выключенными с ясным объяснением. Health=200, зелёный CI и наличие сайта сами по себе не подтверждают доступ к Telegram.

**На момент выпуска этого комплекта:** выполнена документарная и статическая проверка файлов. Тесты приложения, real OAuth, MTProto, IDP tenant и deployment — NOT_RUN.
