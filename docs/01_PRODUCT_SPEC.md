# 01. Postun Beta — продуктовая спецификация

**Редакция 2.0-beta · 04.11.2026.** Канонический документ функциональных требований. Postun — экспериментальный проект в открытом бета-тестировании, а не стабильная версия с гарантией доступности.

## 1. Объём первого релиза

Сразу готовим публичную бету по адресу postun.org и открытый код в AiReformator/postun. На главной странице, в кабинете, документации, описании MCP и заметках релиза явно указываем Beta. Приглашение: «Присоединиться к бета-тестированию». Нельзя показывать неподтверждённую интеграцию как работающую.

Postun выполняет авторизованные запросы к Telegram. Анализ, расписание и задачи остаются у внешнего ИИ-клиента. Не создаём собственную модель, CRM, планировщик мониторинга или индекс всех сообщений. Runtime и пользовательские данные размещаются в Cloudflare. IDP — отдельно выбранный внешний провайдер идентификации администраторов; его не пытаемся запускать внутри Workers.

## 2. Пользовательский путь

1. Открыть postun.org, прочитать условия бета-тестирования и фактическую политику обработки данных.
2. Войти через официальный Telegram OIDC: запрашивать openid и profile, не запрашивать телефон без необходимости. Проверять токен на сервере. OIDC subject и числовой Telegram ID — разные поля.
3. Отдельно подключить собственный Telegram-аккаунт через MTProto QR-вход; при необходимости пройти штатную двухэтапную проверку. Дополнительный аккаунт подтверждается отдельно.
4. В кабинете видеть подключённые аккаунты, разрешённые ИИ-клиенты, квоту и функцию отключения. Ни один ID из формы не доказывает владение аккаунтом.
5. Добавить https://mcp.postun.org/mcp в совместимый клиент. OAuth Postun выдаёт доступ только к выбранным аккаунтам и функциям. Новые привязанные аккаунты не добавляются автоматически в старое разрешение.
6. Получать переписку, результаты поиска и документы. До каждой операции сервер проверяет владельца, разрешение и лимит.
7. Отключить конкретного ИИ-клиента, Telegram-сессию или удалить профиль. Эти действия имеют разные последствия и отдельные подтверждения.

## 3. Каталог read-only инструментов

| Инструмент | Результат | Основное ограничение |
|---|---|---|
| list_accounts | Подключённые аккаунты владельца | Только аккаунты текущего grant |
| list_dialogs | Чаты, группы и каналы | Пагинация; по умолчанию 50, максимум 100 элементов |
| get_history | История выбранного диалога | Даты и непрозрачный курсор; не весь архив одним ответом |
| search_messages | Поиск по доступной переписке | При ограничении чатов глобальный поиск запрещён, если нельзя обеспечить фильтрацию |
| search_channels | Поиск доступных публичных каналов | Не обещать полный каталог или обход ограничений Telegram |
| get_channel_posts | Публикации выбранного канала | Пагинация, дата или ID; без фоновой подписки сервиса |
| get_media_info | Размер, MIME и метаданные файла | Без предварительного скачивания |
| get_media | Файл либо защищённый способ получения | Только проверенный способ для соответствующего клиента |

Scopes: accounts:read, dialogs:read, messages:read, channels:read, media:read. Сервер отклоняет запрещённый вызов независимо от подсказок MCP. Не регистрировать send/edit/delete, управление контактами или участниками. Возвращаемая ссылка на сообщение — поле результата, отдельный инструмент для неё не нужен.

Функции каналов входят в план беты; включаются после функциональных и security-тестов. В таблице совместимости отмечаются отдельно. Не добавлять скрытые платные операции Telegram.

## 4. Файлы

Продуктовый потолок — 512000000 байт. Реально включённый максимум задаётся MAX_FILE_BYTES и не может превышать наибольший успешно испытанный размер. Сначала чтение метаданных, затем поток с ограниченными буферами; никаких полных base64/ArrayBuffer файлов в MCP JSON.

Два раздельных результата приёмки: FILE_DOWNLOAD — пользователь скачивает оригинал; FILE_ATTACHMENT — конкретный ИИ-клиент действительно получает вложение. Ссылка не равна вложению. Общий лимит ручной загрузки ChatGPT не является гарантией MCP-передачи. При отсутствии поддерживаемого механизма прямо показывать доступный вариант, а не симулировать загрузку.

В бете нет R2, долговременного файлового кэша, распаковки архивов, OCR или транскрибации. Для возобновления потока повторно проверяются доступ, диапазон и срок действия capability. Содержимое не записывается на диск или в БД.

## 5. Бесплатный тариф и будущая монетизация

На первом этапе только beta_free. Лимит беты (решение владельца 2026-11-05) — 10 000 успешных логических операций в сутки UTC (`BETA_DAILY_SUCCESS_LIMIT`); месячный счётчик сохраняется для учёта (`BETA_MONTHLY_SUCCESS_LIMIT` = 310 000, не ниже 31 × суточного). Это конфигурация, а не жёстко зашитое значение; суточный и месячный лимиты проверяются в одной атомарной резервации. Учёт на владельца Postun, определяемого primary verified Telegram ID, суммарно по его связанным аккаунтам и ИИ-клиентам. Дополнительная привязка не умножает квоту.

Служебные discovery, tools/list, OAuth, вход и refresh не расходуют пользовательские операции. Внутренние Telegram RPC и чанки не считаются отдельными MCP-операциями. Ошибка не считается успешным вызовом. Байты учитываются отдельно по фактически выданному потоку, в том числе при частичной загрузке и повторной передаче.

Храним месячные success_count и out_bytes; не храним историю запросов. Начальную квоту трафика можно задать отдельно после измерений. Платежей, заказов, Stars-инвойсов и gift-кодов в первом этапе нет.

Для второго этапа сохраняем стабильные principal_id, primary Telegram ID, account_id и grant_id. Будущая покупка меняет entitlement, а не Telegram-сессию. Покупатель и получатель могут различаться; подарок по ID не даёт доступа к данным получателя и не должен раскрывать факт его регистрации. Правила оплаченных периодов разрабатываются отдельно.

## 6. Публичная бета и обратная связь

На лендинге: назначение, Beta badge, приглашение тестеров, инструкция подключения, проверенные клиенты, ограничения, минимизация данных, ссылка на GitHub и канал безопасной обратной связи. На кабинете — текущие доступные функции и ограничения, а не общий рекламный список.

До подключения пользователь подтверждает участие в экспериментальном проекте и передачу выбранных данных своему ИИ-провайдеру. Не обещать SLA, отсутствие ошибок, абсолютную конфиденциальность или возможность восстановить удалённые данные. Бета-статус не ослабляет технические проверки доступа и защиты секретов.

Лендинг может быть опубликован раньше готовности MCP. Пока подключение не прошло приёмку, кнопка подключения объясняет недоступность функции, а не предлагает реальную авторизацию в неисправный сервис. После прохождения проверок регистрацию открываем для бета-тестеров на том же домене без смены идентичностей.

## 7. Что не входит в бету

Платежи, массовые рассылки, write-инструменты, собственные ИИ-задачи, постоянные соединения ради мониторинга, контентная аналитика, хранение архивов, Google-инфраструктура, VPS и Docker-порт. Самостоятельная установка в этой редакции означает установку в собственный Cloudflare-аккаунт.

Признак готовности — принятые сценарии из 05_ACCEPTANCE.md и подтверждённый deployment, а не наличие README или зелёной сборки.
